\section{Introduction}
\label{sec:introduction}

Why do two graph representations disagree about whether a pair of graphs is
different? Consider two graphs with the same numbers of nodes and edges and
the same degree distribution, but with different cycle structure. A degree
representation collapses the pair. A cycle representation need not. Neither
answer is intrinsically wrong: each follows from what the representation was
built to see.

This example raises the question that motivates the paper: can structural
visibility itself become a programmable choice? Existing methods offer many
useful views---neighborhoods, paths, graphlets, rooted pairs---but each usually
arrives with its own notation, implementation, and feature construction. It is
then hard to ask what changes when two views are combined, or to attribute a
new distinction to the structure that exposed it.

Abstract Graphs give us a way to pose that comparison in one language. An
Abstract Graph couples a base graph to an interpretation graph whose nodes
denote mapped structures in the base graph. A cycle, for example, can remain an
object in the interpretation graph while retaining the concrete nodes and
edges that form it. Operators act within this space:
\begin{equation}
  o:\mathcal{A}^{k}\to\mathcal{A}.
\end{equation}
Every output is therefore available to another operator. Neighborhoods can be
paired, cycles can be combined with paths, and domain-specific decompositions
can participate in the same expressions.

Closure is the construction that makes the comparison possible, not an
empirical finding. It provides composability, not refinement. Applying
another operator does not necessarily produce a finer representation, and a
longer expression need not distinguish more graphs. It may expose a new
structure, aggregate an old one, or replace one structural view with another.
Whether the resulting expression separates a graph pair is something to
measure, not something guaranteed by the algebra.

Adding a structural view requires only a function that groups the nodes of a
NetworkX graph. The library turns those groups into mapped interpretation
nodes, after which the operator can participate in the same expressions. This
is an extension mechanism rather than evidence of scientific advantage; the
study therefore evaluates the representations it produces, not the brevity of
the interface.

The scientific question is whether this common intermediate representation
does more than organize familiar feature extractors. We first test exact
translations of path, Weisfeiler--Lehman, and NSPDK representations against
independent implementations. We then compare genuine graph-valued composition
with both its atomic components and the lossless concatenation of their final
feature vectors. Predeclared graph pairs and held-out generator settings reveal
which distinctions are gained, retained, or lost; the base mappings identify
the structures responsible for those changes. Finally, runtime, memory, and
representation size show whether a useful distinction justifies its cost.
Pooling, hashing, and simple linear probes remain diagnostic controls rather
than independent claims.
